# 宿主机网络设计

## 支持范围

首期写入 Linux Bridge 和 802.1Q VLAN Interface。Bond、Team、OVS、VXLAN、
macvlan、macvtap、Tap 和 vnet 只读展示。

发现物理接口、地址、路由、规则、Bridge/Port、VLAN、MTU、Carrier、Driver、
PCI 地址、VM 关系以及 NetworkManager、networkd、Netplan、ifcfg 和 interfaces。

## 后端判定

不能只检查配置文件。必须综合：

- 服务是否运行
- 目标接口实际由谁管理
- 当前配置来源
- cloud-init 生成标记
- 多后端冲突

无法唯一、安全确认写入后端时，将目标接口标记为只读并展示原因。

## 事务式变更

1. 采集当前状态和配置快照。
2. 识别 SSH 目标、管理接口、管理 IP 与默认路由。
3. 生成并校验目标配置。
4. 生成命令/文件 Diff 与依赖影响。
5. 评估低、中、高或可能失联风险。
6. 创建独立于 SSH 会话的一次性回滚任务。
7. 应用配置并尝试重新建立 SSH。
8. 验证管理 IP、默认路由、DNS 和预期接口。
9. 等待管理员确认；确认后取消回滚。
10. 超时或失败自动回滚并验证。

## 回滚能力

systemd 节点优先使用随机名称的 `systemd-run --on-active` 瞬态 unit。脚本与快照
只放在允许的临时目录，最小权限，执行/取消后清理。

若不存在 systemd-run、atd 或经验证的等价独立一次性调度器：

- 禁止修改当前管理接口、管理 IP、默认路由、管理 Bridge 或管理 VLAN。
- 不影响管理链路的低风险操作仍须经过预检和验证。
- 禁止使用未经验证的 `nohup sleep` 方案冒充可靠回滚。

## 并发与恢复

同一节点只允许一个网络 Apply。计划、快照、回滚句柄、确认期限和状态全部持久化。
容器重启后先查询远端回滚实体和当前网络状态，再决定确认、回滚或人工干预。

节点移除前取消或核实 Nexora 临时回滚任务并清理临时管理文件，不改变最终业务网络。
