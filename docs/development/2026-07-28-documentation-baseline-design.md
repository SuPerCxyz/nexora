# Nexora 文档基线设计

日期：2026-07-28

## 目标

把产品提示词和后续审查结论转换为仓库内可持续维护的权威文档，使新的代码
Agent 不依赖聊天上下文即可确定范围、架构、安全门禁、测试要求和恢复入口。

## 方案

采用三层信息架构：

1. `AGENTS.md` 只保存不可绕过的规则、阅读顺序和交付门禁。
2. 根目录文档保存项目状态、架构索引、路线图、ADR、安全和测试状态。
3. `docs/` 保存产品与架构专题，按任务选择性加载。

不把完整规格塞入 `AGENTS.md`，避免每次任务加载无关内容。专题之间通过根目录
索引连接，同一约束只保留一个权威定义，其他文档使用链接或摘要。

## 验收

- 后续 Agent 能从 `AGENTS.md` 找到必读材料。
- 原始需求的最高优先级约束已落盘。
- 审查发现的身份、SSH、任务、XML、媒体和网络问题有明确决策。
- 状态、路线图和测试文件包含精确恢复入口。
- 文档没有 TBD、TODO 或依赖聊天上下文的占位描述。
