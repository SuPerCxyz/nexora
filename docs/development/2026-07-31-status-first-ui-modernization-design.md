# 状态优先 UI 现代化设计

## 目标

将 Nexora 从“直接展示实现细节的技术控制台”调整为现代、安静、状态优先的运维
工作台。管理员进入页面后应先看到资源是否正常、哪里需要关注和可执行的常用操作，
再按需进入 UUID、hash、XML、原始能力和任务细节。

## 已确认方向

- 以视觉方案 A“任务优先”为基础，但弱化任务和活动信息，改为状态优先。
- 页面标题、紧凑状态按钮、更新时间和常用操作位于同一视觉区域。
- 不使用大块“运行状态良好”说明；正常状态只显示简短按钮，异常时才展开原因。
- 运行摘要使用横向属性行，不与子系统状态争夺独立卡片层级。
- 子系统状态占满内容宽度，每个子系统使用横向列表行。
- 技术详情默认折叠，不从业务页面删除，保证诊断能力。

## 信息层级

每个资源详情页按以下顺序组织：

1. 资源名称、所属范围、状态按钮、更新时间和常用操作。
2. 电源、运行时间、自动启动、最近快照等紧凑属性。
3. CPU、内存、磁盘、网络等核心状态指标。
4. 横向子系统列表：图标、名称、关键配置、状态和详情入口。
5. 仅异常项显示简短原因与建议。
6. UUID、hash、XML、原始输出和高级配置放入“底层详情”。

正常状态使用“正常”“运行中”“已连接”等短文案。禁止用长段落重复解释正常结果。
错误和风险必须说明影响与下一步，但不展示原始 SSH stderr 或内部异常。

## 页面改造

### 总览

- 以环境健康、运行/停止资源数、节点可达性和需关注项为主。
- 最近任务降为次级区域，仅展示失败或进行中的必要摘要。
- 不使用营销式英雄区或大号欢迎语。

### 资源列表

- 首列突出名称、状态和所属节点，技术 ID 使用次级文字或详情抽屉。
- 支持状态、节点和类型筛选；危险操作不放在行内主操作区。
- 空状态说明当前事实，并只提供一个明确下一步。

### 节点与虚拟机详情

- 采用已确认的状态优先结构。
- 子系统列表横向展示，整块占满内容宽度。
- 正常项保持紧凑；异常项可展开影响、建议和相关操作。
- 高频动作直接显示，低频和危险动作收入“更多操作”。

### 创建与变更流程

- 长表单按“基础信息、计算、存储、网络、高级选项”分组并渐进展开。
- 预览页先显示变更摘要、风险和影响，再显示 XML Diff。
- 字段继续保持可见 label、就地错误和明确默认值。

## XML 与技术内容

- XML 使用格式化缩进展示，不输出未格式化单行文本。
- 使用等宽字体、行号、语法着色、复制按钮和独立滚动区域。
- 默认折叠在“底层详情”或“查看 XML”中，避免占据主页面。
- XML Diff 保留新增、删除和上下文区分，并支持复制完整内容。
- 长 UUID、hash、路径和 URI 必须可复制且安全换行，不撑破布局。
- 技术内容仍需 HTML 转义；不得通过前端字符串拼接修改 XML。

## 视觉规则

- 保留现有品牌蓝、青绿和暖色状态体系，正文承载面保持白色或近白色。
- 降低卡片数量和阴影强度，优先使用全宽区块、分隔线和横向列表。
- 状态必须同时使用颜色、图标和文字；触控目标至少 44px。
- 动效仅用于展开、状态刷新和操作反馈，时长 150 至 200ms。
- 375、768、1024、1440px 均不得横向溢出或发生文字遮挡。

## 实施边界

- 不改变内部 Session API、后端领域模型、任务状态机或安全确认流程。
- 不引入 SPA、远程字体、CDN 或新的前端框架。
- 继续使用 Jinja2、HTMX、Tabler UI、Tabler Icons 和少量原生 JavaScript。
- 第一阶段改造共享样式、总览、列表、节点详情、VM 详情和创建流程。
- 任务、审计、控制台和网络拓扑只同步共享视觉语言，不重做业务交互。

## 验证

- 更新模板回归测试，验证关键状态、操作和折叠技术详情仍可访问。
- Browser QA 覆盖总览、列表、节点、VM、创建和 XML/Diff 页面。
- 检查 375/768/1024/1440px、键盘导航、44px 触点、控制台和 HTMX 请求。
- 对 XML 视图验证格式化、转义、复制、长行滚动和 Diff 可读性。

## 风险

- 页面重组不能隐藏安全预检、确认和失败恢复入口。
- “正常”必须来自已有权威状态，不能由前端根据缺失数据推断。
- 无状态数据时显示“等待采样”或“未知”，不得显示绿色正常状态。
