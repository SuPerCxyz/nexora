# 验收与非功能基线

## 首个可用版本

必须满足 `docs/product/REQUIREMENTS.md`、`docs/product/SCOPE.md` 和各架构专题。
重点验收：

- 单容器、SQLite、无外部队列/数据库、管理节点无需 KVM。
- 单管理员、严格 Host Key、加密凭据和内部 Session API。
- 多节点无 Agent 接入，已有资源自动发现并统一管理。
- 带外变更检测，未知 XML 保留。
- Cockpit Machines 核心 KVM 功能、Linux/Windows Guest。
- dir/NFS netfs、媒体 ISO、镜像复制。
- Bridge/VLAN 与断线自动回滚。
- noVNC、串口、快照、克隆和关机迁移。
- 长任务进度、重启恢复、审计和节点移除零残留。

## 初始容量目标

以下是首个压测前的设计目标，调整必须写 ADR：

- 至少 20 个节点，每节点 200 台 VM 的索引、分页和筛选。
- 普通列表请求不得同步扫描全部远端资源。
- SSH、文件复制、控制台、全局任务和单节点查询分别限流。
- 默认单条命令合计输出上限 4 MiB，超出时保存截断标记。
- 默认单份 Domain XML 上限 10 MiB，并额外限制深度和节点数。
- 媒体和镜像始终流式处理，不进入进程内完整缓冲。
- 性能历史默认低频保存 24 小时，可关闭并定期清理。

## 可靠性

- SQLite WAL 断电恢复和 integrity check 必须演练。
- 数据库事务不得覆盖远端 I/O。
- 任务重启恢复先验证外部状态，不盲目重放。
- 备份、恢复和升级回滚命令必须在发布前实际演练。
- 网络失联故障注入必须证明回滚不依赖原 SSH 会话。

## 安全与可访问性

- 认证、CSRF、XSS、SSRF、XXE、命令/参数注入和路径逃逸有测试。
- 容器非 root、无 privileged、无宿主敏感 socket。
- 发布生成 SBOM、许可证清单和漏洞扫描结果。
- 页面以 WCAG 2.1 AA 为基础目标；状态不只依赖颜色。

## 验收证据

每项验收必须记录环境、命令、版本、退出码和必要的脱敏输出。无法执行的验证列入
`TEST_STATUS.md`，不得以人工预期替代通过证据。
